# Mali 定制说明

本目录记录源码 fork 与官方版本之间的关系，不保存生产配置。

## 分支

- `main`：官方 `main` 的只读镜像。
- `mali`：唯一的日常定制分支，检查通过后直接提交和推送。
- `sync/upstream-*`：官方 Release 升级分支，验收后合入 `mali`。

日常功能开发不要求创建额外分支或 PR。大型实验可临时建分支，但不是固定流程。

## 升级规则

1. 定时或手动检查官方最新 Release。
2. 安全快进 fork 的 `main`。
3. 从 `mali` 创建同步分支并合入官方标签。
4. 有冲突立即停止，人工处理后继续。
5. PR 通过官方测试和 Mali 镜像构建后再验收、合并。

当前基线和定制版本见 `upstream.env`。

同步工作流使用仓库 Secret `UPSTREAM_SYNC_TOKEN`。令牌必须能够写入
`pyt111/sub2api` 的代码、Pull Request 和 Workflows；令牌内容不得提交到仓库。

## 定制清单

- `0.1.170-ops.2`：以独立 `session-refresh` 模块合并并发登录续期请求，公共鉴权入口仅保留最小接入。
- `0.1.168-ops.2`：版本检查忽略 `-ops.*` 定制后缀，同一官方基线不再误报升级。
